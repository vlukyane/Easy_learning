## Что это

**Правила хуков:** вызывать только на **верхнем уровне** компонента (не в `if`, не в цикле, не в вложенной функции). React помнит state **по порядку вызовов**. Пропустил хук через `if` — на следующем рендере порядок съехал, чужой state в чужой переменной.

**Custom hook** — функция `useЧтоТо`, внутри которой обычные хуки. Это **переиспользуемая связка**, не ускорение. `useStudyBoard` прячет load/save/add — структура, не оптимизация.

**`memo` / `useMemo` / `useCallback`** — **кэш**:

- `memo(Component)` — не перерисовывать, если props те же по сравнению;
- `useMemo(() => расчёт, [deps])` — помнить результат расчёта;
- `useCallback(fn, [deps])` — помнить ту же функцию (та же ссылка).

Кэш **стоит** памяти и сравнения. На 15 карточках часто **вреднее**, чем польза: устаревшее замыкание, сложнее читать, ложная уверенность.

## Зачем

Без правил хуков баги «иногда NaN после клика» не ловятся глазом. Без понимания memo новичок оборачивает всё и чинит баг ещё одним `useCallback`, пока доска не оживёт.

## Как работает

Вынеси persist в `useStudyBoard()` — custom hook возвращает `{ cards, add, move }`.

Когда надо: стабильная ссылка колбэка в зависимость эффекта; расчёт, который реально дорогой (не склейка строк).

Когда не надо: оборачивать каждую кнопку; `useMemo(() => cards.filter(...), [cards])` ради трёх элементов.

Профилировщик React в DevTools > Profiler — посмотри, кто рендерится при добавлении карточки, **до** того как вешать memo.
