## Что это

**React** — библиотека UI: ты описываешь, **как экран должен выглядеть при таких данных**, а не «найди div и пришей кнопку». Компонент — функция: на входе данные, на выходе описание интерфейса.

**Virtual DOM / сверка на пальцах:** React строит новое **описание** дерева (объекты в памяти). Сравнивает с предыдущим описанием. В настоящий DOM пишет только отличия. Ты не вызываешь `appendChild` на каждую карточку сам — иначе обойдёшь сверку и сломаешь модель.

**JSX** — не HTML и не строка. Это синтаксис, который компилируется в вызовы вроде `React.createElement`. Похоже на теги, но это JavaScript. Поэтому `className`, не `class`; `htmlFor`, не `for` — слова `class` и `for` в JS заняты.

Аналогия: в JS-теме ты сам маляр (кисть по стене). В React ты сдаёшь чертёж «стены с тремя окнами», маляр-React красит сам.

## Зачем

Императивный DOM разрастается: добавил карточку в массив — забыл нарисовать; удалил — остался слушатель. Боль — рассинхрон «данные одни, на экране другое». React делает экран функцией от state: сменил state — описание пересчиталось.

## Как работает

Меняется state → React вызывает компоненты снова → получает новое JSX-дерево → сверка → патч DOM. Побочные эффекты (storage, фокус) — отдельно, через хуки, не в середине расчёта разметки.

TypeScript в этом курсе не используем. Шаблон `react` (JSX), не `react-ts`.
