## Что это

**State** — память компонента **между рендерами**. Обычная `let` внутри функции сбрасывается каждый вызов. `useState` хранит значение у React.

`useState(начальное)` возвращает пару: **текущее значение** и **setter**. Setter не меняет переменную «прямо сейчас» как `x = 1`. Он **ставит обновление в очередь**: React потом перерисует компонент с новым значением.

**Иммутабельность:** массив/объект в state не редактируют дыркой (`push`, `card.title =`). Делают **новый** массив/объект, чтобы React увидел «ссылка другая — надо сверку». Старая ссылка = «ничего не изменилось», экран застынет.

**Контролируемый инпут:** React — хозяин `value`. Поле показывает `title` из state; каждый символ — `setTitle`. Без `value` инпут живёт своей жизнью (DOM), state отстаёт — submit отправит пустоту.

**Подъём состояния:** общий предок держит **единственный** массив карточек. Колонки получают кусок через props. Если у каждой колонки свой массив, перенос карточки — синхронизация трёх близнецов, они разъедутся.

## Зачем

Боль без state: кликнул — ничего. Боль с тремя массивами: карточка исчезла из «сделать» и не появилась в «работе». Боль с `push`: в консоли массив полный, UI старый.

## Как работает

```jsx
const [cards, setCards] = useState([]);
const [title, setTitle] = useState("");
```

State живёт в ближайшем общем предке. Один массив `cards` с полем `column`.

Контролируемый инпут: `value={title}` + `onChange={(e) => setTitle(e.target.value)}`.

Обновления иммутабельно: `setCards([...cards, next])`, не `cards.push`.
