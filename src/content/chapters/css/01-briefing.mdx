## Что это

**CSS** (Cascading Style Sheets) — правила вида: **для каких элементов** (селектор) **какие свойства** (`color`, `margin`, `display`). HTML по-прежнему несёт смысл. CSS отвечает только за **представление**: цвет, размер, ряд или столбик.

Аналогия: HTML — ноты, CSS — как оркестр играет (громче, темнее, шире). Партитура не меняется, если дирижёр попросил иначе.

Три механизма, из-за которых «класс не применяется»:

1. **Каскад** — если несколько правил попали в один элемент, побеждает не «последнее в файле всегда», а комбинация: происхождение (браузер / автор / `!important`) + порядок. Авторские правила бьют браузерные. Среди авторских позже в файле бьёт раньше, *если специфичность равна*.
2. **Наследование** — часть свойств дети берут у родителя: `color`, `font-family` — да. `margin`, `padding`, `border`, `width` — **нет**. Дочерний абзац не получит отступ родителя «автоматом».
3. **Специфичность** — счёт очков селектора: элемент слабее класса, класс слабее id. Более «тяжёлый» селектор бьёт более поздний лёгкий.

## Зачем

Без этой модели ты красите в DevTools, обновляешь страницу — и цвет откатывается; или пишешь `.card { color: red }` и не понимаешь, почему текст всё ещё серый (победил другой селектор). Браузер не «ломается» — он считает каскад.

## Как работает

Браузер для каждого элемента собирает подходящие правила, отбрасывает проигравшие (в DevTools они зачёркнуты), потом рисует. Если свойства нет в правиле и оно наследуемое — берёт у предка. Если не наследуемое — берёт начальное значение (`margin: 0` у многих тегов — из таблицы браузера).

Три причины «не применилось» коротко: селектор мимо; другое правило специфичнее; свойство не наследуется.
