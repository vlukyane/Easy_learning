## Что это

**Viewport** — видимое окно страницы. На телефоне это узкая полоска, не ширина «настоящего» монитора дизайнера.

**CSS-пиксель** ≠ физическая точка экрана. У Retina в одном CSS-пикселе несколько аппаратных. Media query смотрит на **CSS-ширину вьюпорта**, не на «дюймы телефона в магазине».

**Media query** — условие вокруг блока правил: «если ширина окна меньше 700px, переопредели раскладку». Это не другой файл и не JS.

**Mobile-first** в одном абзаце: сначала пишешь стили для узкого экрана (колонка, всё столбиком), потом в `@media (min-width: …)` добавляешь ряд. Так меньше «отмен» сложных десктоп-правил. В пилоте допустим и `max-width`: главное — две ширины без скролла вбок.

## Зачем

Без `viewport` в HTML телефон думает, что страница ~980px, масштабирует всё мелко — твои `@media (max-width: 700px)` **не сработают**, как ты ждёшь: «логическая» ширина всё ещё десктопная. Без медиазапроса три колонки flex на 360px сплющатся или вылезут за край.

## Как работает

`viewport` meta должна быть с HTML-темы. Без неё media queries врут на телефоне.

```css
@media (max-width: 700px) {
  .board {
    flex-direction: column;
  }

  .layout {
    grid-template-columns: 1fr;
  }
}
```

Проверка: DevTools → Toggle device toolbar, 360px и 1200px. Горизонтального скролла быть не должно.

Меню: на узком экране ссылки могут идти столбиком. Выпадающее «бургер» без JS можно не делать — достаточно столбика.
