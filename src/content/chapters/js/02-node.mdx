Vite и npm появятся в React, но Node нужен уже сейчас: запускать мелкие скрипты и позже `npx`. Ставим **nvm**, не случайный Node с сайта «кнопкой».

macOS + zsh.

## Что это

**Node.js** — **рантайм**: машина, которая выполняет JavaScript **вне браузера**. Браузер нужен, чтобы показать страницу. Node нужен, чтобы крутить **инструменты**: npm, Vite, скрипты сборки, учебный `hello.js`. Это не замена Chrome и не «сервер сам по себе» — это программа `node` в терминале.

**npm** — две вещи сразу: **реестр** готовых пакетов в интернете и **программа**, которая скачивает их в папку `node_modules` и записывает версии в `package.json`. Пока мы только проверяем, что `npm -v` есть.

**nvm** — переключатель версий Node. Проект А хочет 18, проект Б — 22. Без nvm глобальный Node с сайта дерётся с Homebrew-Node, и «у меня работало» ломается на другой машине.

**PATH** — где оболочка ищет `node` и `npm`. nvm подменяет путь, когда ты делаешь `nvm use 22`. Старый таб терминала про это не знает.

`node file.js` выполняет файл в Node: есть `console` и `process`, нет страницы, нет кликов, нет `document`.

## Зачем

Без Node не будет Vite и `npm create`. Без nvm через полгода всплывёт Node 14 «откуда-то» и установка курса разъедется. Боль без этого: «command not found: npm» или «несовместимый движок» на пакете, который ждёт 22.

## Как работает

Ставишь nvm → он дописывает загрузку в `~/.zshrc` → **новый** таб поднимает nvm → `nvm install 22` качает бинарник Node в домашнюю папку nvm, не в `/usr` системы → `nvm use 22` ставит этот бинарник первым в PATH этой сессии.

`.nvmrc` с текстом `22` — записка для папки: `nvm use` без номера читает файл.

## 1. Есть ли nvm

<Command cwd="~" title="Проверка nvm" code={`command -v nvm || echo "nvm not found"
node -v 2>/dev/null || echo "no node"`} />

Если `nvm` есть — переходи к `nvm install 22`. Если Node без nvm (Homebrew) — всё равно поставь nvm: так не сломаешь системный Python/браузер.

## 2. Установка nvm

<Command cwd="~" title="Скрипт nvm" code={`curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash`} />

Скрипт допишет строки в `~/.zshrc`. **Закрой терминал полностью** и открой снова. Либо:

<Command cwd="~" title="Подхватить nvm в текущей сессии" code={`export NVM_DIR="$HOME/.nvm"
. "$NVM_DIR/nvm.sh"
nvm --version`} />

Ожидание: номер версии nvm, не `command not found`.

Типичная поломка: открыт старый таб терминала без нового `.zshrc`. Новый таб.

## 3. Node 22

<Command cwd="~" title="Поставить и включить Node 22" code={`nvm install 22
nvm use 22
node -v
npm -v`} />

Ожидание: `v22.…` и версия npm (обычно 10+).

В корне этого репозитория уже есть `.nvmrc` с `22`. Для папки js:

<Command cwd="projects/web/js" title="Локальный .nvmrc" code={`echo "22" > .nvmrc
nvm use`} />

`nvm use` без номера читает `.nvmrc`.

## 4. Два запуска

<Command cwd="projects/web/js" title="Node без DOM" code={`echo 'console.log("node ok", process.version)' > hello.js
node hello.js`} />

Ожидание: `node ok v22…`

Браузерный файл так не проверяют.

### Linux / Windows

- Linux: тот же install.sh, bash/zsh.
- Windows: [nvm-windows](https://github.com/coreybutler/nvm-windows) — другой бинарь, команды `nvm install 22` похожи. Не мешай его с WSL-nvm: выбери одну среду.

Vite в этой главе не создаём.
