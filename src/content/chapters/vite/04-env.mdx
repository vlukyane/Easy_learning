## Что это

Код React **уйдёт в браузер пользователю**. Всё, что попало в клиентский бандл, можно увидеть в DevTools. Поэтому переменные окружения на клиенте — не «секретный сейф», а публичные настройки (заголовок доски, публичный URL API).

**Префикс `VITE_`** — явный opt-in: «эту переменную **можно** вшить в клиент». Без префикса Vite **не подставит** её в `import.meta.env` — защита от случайного `SECRET` из `.env`.

Файлы `.env`, `.env.local`, `.env.production` — разные слои. Для курса достаточно одного `.env`. Смена env требует **перезапуска** `npm run dev`: значения вшиваются на старте, не при каждом сохранении компонента.

## Зачем

Без префикса «почему undefined». С ключом Anthropic в Vite — ключ в бандле у всех, кто открыл сайт. Боль и стыд.

## Как работает

Файл `.env` в корне приложения:

```
VITE_BOARD_TITLE=Доска учёбы
```

Чтение: `import.meta.env.VITE_BOARD_TITLE`.

`.env` не коммить, если там токены. Для учебного заголовка можно `.env.example`:

<Command cwd="projects/web/react" title="Пример env" code={`echo 'VITE_BOARD_TITLE=Доска учёбы' > .env.example
cp .env.example .env`} />

TypeScript-типы env — вне курса; в JS просто строка или undefined.

<Checkpoint>
**Готово, когда:** смена VITE_BOARD_TITLE после рестарта dev видна на странице, секретов в клиенте нет.

**Как проверить:** поменяй строку, Ctrl+C, npm run dev, обнови Chrome. Без префикса — undefined.

**Ещё рано, если:** заголовок всё ещё литерал в JSX; ключ модели в Vite; не перезапускал сервер и думаешь, что «env не работает».
</Checkpoint>
