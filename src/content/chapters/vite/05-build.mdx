## Что это

**`dist`** — статическая папка: `index.html` + JS/CSS с хешами. Её можно положить на **любой** хостинг статики (GitHub Pages, Netlify, обычный nginx). Сервера Node на проде для этой доски нет.

**`npm run preview`** — локально раздать **уже собранное**, как хостинг. Это **не** dev: нет HMR, нет преобразования JSX на лету — только файлы из `dist`. Нужно, чтобы поймать баги бандла до выкладки.

## Зачем

Dev прощает относительный import без расширения или смешение default/named — прод падает. Без `build` ты не знаешь, уедет ли доска на хостинг. Без `preview` открываешь `dist/index.html` как `file://` и ломаешь пути `/assets/…`.

## Как работает

<Command cwd="projects/web/react" title="Production-сборка и локальный просмотр" code={`nvm use 22
npm run build
npm run preview`} />

`build` пишет в `dist/`. Ошибки «не нашлось .jsx» часто всплывают только здесь (неверный путь, смесь default/named export).

Очистка кэша Vite, если dev «залип»:

<Command cwd="projects/web/react" title="Сброс кэша" code={`rm -rf node_modules/.vite
npm run dev`} />

Не коммить `dist/` без нужды. Для проверки DoD dist достаточно локально.
