## Что это

**Middleware** — обёртка вокруг стора: перехватывает `set`/`get`. **`persist`** читает и пишет **storage** (по умолчанию `localStorage`) сам: после изменения — stringify, при старте — parse обратно в объект.

**Гидрация** — момент, когда из storage подставили данные. Первый рендер часто ещё пустой (сервер/клиент), второй — уже с карточками. Мерцание «пустая доска на кадр» — часто это, не баг add.

**Версия схемы:** поле `version` + функция `migrate`. Поменял форму карточки (`column` → `status`) — старый JSON без миграции сломает UI молча.

## Зачем

Свой `useEffect` + `stringify` ты уже делал. Middleware не дублирует идею — убирает забытый save и разъезд ключей. Без `version` учебный эксперимент с полями убивает доску студента.

## Как работает

```js
import { persist } from "zustand/middleware";

export const useBoard = create(
  persist(
    (set, get) => ({ /* ... */ }),
    { name: "study-board-z", version: 1 },
  ),
);
```

Ключ `name` — не ключ JS-темы и не ключ портала.

При мерцании смотри `onRehydrateStorage`.

Конфликт с `load()` из JSON: persist побеждает, если данные уже есть; load — только если storage пуст.
