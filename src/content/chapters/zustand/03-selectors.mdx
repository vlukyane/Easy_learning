## Что это

**Селектор** — функция `(state) => кусок`. Zustand сравнивает **результат** с предыдущим (по `Object.is`: для примитивов по значению, для объектов по **ссылке**).

Вернул тот же номер длины — колонка может не рендериться. Вернул **новый массив каждый раз** (`filter` без мемоизации) — ссылка всегда новая → **всегда ререндер**. Селектор колонки как раз про это: не «прочитать cards», а «дать стабильный снимок, пока колонка не изменилась».

## Зачем

Подписка на весь стор = Context. Смысл Zustand теряется. Боль: Profiler показывает, что «Готово» перерисовывается при добавлении в «Сделать» — виноват `filter` в селекторе, не «React сломан».

## Как работает

Колонка «Готово»:

```js
const done = useBoard((s) => s.cards.filter((c) => c.column === "done"));
```

Проблема: `filter` каждый раз новый массив → ререндер всегда. Лучше хранить карточки как есть и фильтровать **или** мемоизировать селектор (`useShallow` из `zustand/react/shallow` для объектов).

Для списка id:

```js
const ids = useBoard((s) =>
  s.cards.filter((c) => c.column === "todo").map((c) => c.id).join(),
);
```

Грубо, но стабильно по содержимому. Нормальный путь: селектор `s => s.cards` + фильтр в компоненте колонки, если колонок три и карточек мало; для учёбы вынеси `selectColumn(column)` и сравнивай длину+id.

Проверь Profiler: добавление в «Сделать» не должно перерисовывать «Готово», если селектор той колонки вернул тот же снимок.
