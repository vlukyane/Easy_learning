Синтетика даёт идеальную разметку. Это нормально. Опасность — утечка test в train: один и тот же шаблон номера, один перевозчик, копипаста адресов.

Для отладки можно 2k документов. К LoRA-главе наращивай к десяткам тысяч, если железо позволяет; если нет — честно уменьши N и отрази это в выводе «зависит от объёма».

<Action title="Разведи шаблоны по сплитам осторожно">
Либо все шаблоны во всех сплитах, либо явный generalization-тест на held-out шаблон. Не клади уникальный шаблон только в train.
</Action>

<Trap title="Утечка test в train">
Особенно легко на синтетике. Фиксируй разбиение файлом, не `random` без seed.
</Trap>

<Checkpoint>
**Готово, когда:** test id нельзя встретить в train даже если очень хочется.

**Как проверить:** pytest + открыть splits.json, выборочно grep id.

**Ещё рано, если:** деление «на глаз 80/20» каждый раз разное; нет seed; нет теста пересечений.
</Checkpoint>
