Сначала намеренно слабый агент. Иначе «после защиты 0% ASR» не отличить от «атаки не работали».

<Scaffold path="projects/doorman/src/agent/vulnerable.py">
Склеивает job description и сырой текст резюме в один user-промпт без разметки недоверенного блока. Есть инструмент оценки, нет запрета на смену инструкции. Structured score 1–10 + rationale.
</Scaffold>

Не давай ему инструменты почты/сети даже в baseline — иначе учебный стенд станет опасным. Эксфильтрацию измеряй как *попытку* в тексте выхода («вставь system prompt в rationale»), не как реальную отправку.

<Command cwd="projects/doorman" title="Оценка чистого резюме" code={`python -c "from src.agent.vulnerable import screen; print(screen('data/clean/sample.txt', 'data/job.txt'))"`} />

Зафиксируй поведение на чистых: распределение оценок. Это пригодится для FP.

<Action title="Не чини baseline">
Увидев, что модель «и так не ведётся», не усложняй атаки до бесконечности на этом шаге. Корпус — следующая глава. Здесь нужен воспроизводимый слабый пайплайн.
</Action>

<Practice items={[
  { id: "glue", label: "Vulnerable склеивает резюме и инструкцию без пометки untrusted", hint: "Это намеренно дырявый baseline. Не чини его «чуть-чуть». Иначе нечему сравнивать hardened." },
  { id: "no-email", label: "Нет tool на отправку почты или произвольный HTTP", hint: "Иначе red team уйдёт в настоящий вред. Пилот — score/facts, не эксфильтрация через инструменты." },
  { id: "clean-run", label: "Чистое резюме проходит и даёт структурированный score", hint: "Без атаки пайплайн живой. Если чистое уже ломается — чини парсер, не защиту." }
]}>
Собери дырявый агент и проверь на чистом файле. Корпус атак — следующая глава.
</Practice>

<Checkpoint>
**Готово, когда:** baseline гоняет чистое резюме и готов есть помеченный корпус.

**Как проверить:** один clean PDF/текст → JSON score. В промпте резюме не обёрнуто как untrusted.

**Ещё рано, если:** уже «защитил» vulnerable; есть send_email; чистое резюме падает.
</Checkpoint>
