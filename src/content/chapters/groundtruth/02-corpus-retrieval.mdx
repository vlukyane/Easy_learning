Корпус: открытые судебные акты, статуты, CUAD, Pile of Law — что лицензионно можно класть в `data/corpus/`. Начни с 50–200 документов, не с миллионов.

<Scaffold path="projects/groundtruth/src/ingest.py">
Реализуй `build()`: прочитать файлы из `data/corpus/` и сохранить пары `doc_id` + полный текст (индекс или кэш на диск — как удобно `retrieve`).

**Откуда документы.** Открытые судебные акты, статуты, CUAD, Pile of Law — только то, что лицензионно можно класть в репо. Начни с 50–200 файлов, не с миллионов. Сырьё — в `data/corpus/` (txt/jsonl). Источники и лицензию запиши в README или `data/SOURCES.md`.

**Стабильные id.** `doc_id` станет ключом золота. Бери неизменный ключ: имя файла без расширения (`opinion-2019-0142`) или поле из метаданных. Не генерируй новый uuid на каждый `build()`: иначе `relevant_ids` перестанут существовать.

`build()` идемпотентен: повторный запуск с тем же корпусом даёт те же id. Пустой файл — понятная ошибка, не молчаливый пустой id.
</Scaffold>

<Scaffold path="projects/groundtruth/src/retrieve.py">
Реализуй `retrieve(query, k) -> list[str]`: ранжированный список `doc_id`, длина не больше `k`. Контракт главы и эвала — **id**, не полные тексты (текст можешь держать рядом в индексе).

**v1 — BM25** или простой TF-IDF. Эмбеддинги — v2, когда гейт уже зелёный на детерминированном поиске. Не вызывай LLM «подбери документы»: дорого, флаки, ломает CI.

**Детерминизм.** Один запрос при фиксированном индексе дважды подряд → один порядок. `k` по умолчанию бери из `K` в `src/constants.py` (сейчас 10). Никакого `shuffle`, неупорядоченного `set`, зависимости от времени. При равных скорах — стабильный tie-break (например, лексикографически по id).
</Scaffold>

Детерминизм важен для CI: флаки-гейт хуже отсутствующего гейта. Фиксируй версию эмбеддера, seed, `k`.

В константе `K=10` (или 5). recall@k без зафиксированного k — разные метрики под одним именем.

Сначала сложи корпус и один раз вызови `build()`. Потом ручной запрос из главы — дважды подряд: списки id должны совпасть символ в символ. `k` только из константы, не магическое число в трёх файлах.

<Checkpoint>
**Готово, когда:** один и тот же запрос дважды подряд даёт один и тот же ranked list id, корпус лежит на диске со стабильными `doc_id`, `k` — одна константа.

**Как проверить:** дважды выполни команду «Ручной запрос»; сравни списки — они идентичны. Открой пару файлов в `data/corpus` и перезапусти `build()`: id те же. В коде `K` импортируется из `src/constants.py`, не захардкожен внутри `retrieve`.

**Ещё рано, если:** порядок прыгает от запуска к запуску; id — случайный uuid; `k` разный в retrieve и в голове; корпуса нет, функция всё ещё `NotImplementedError`; в выдаче тексты вместо id.
</Checkpoint>
