**Какие модели и поля:**
- `ClaimIntake`: `claim_id`, `narrative`, `claimed_amount`, `incident_date`, `attachments_meta`.
- `IntakeResult`: те же факты плюс `facts: list[str]` — не сырой completion.
- `ClassifierResult`: `claim_type`, `priority` (`low` | `medium` | `high`), `confidence`.
- `FraudResult`: `risk` (`low` | `medium` | `high`), `flags: list[str]`, `send_to_human: bool`.
- `Assessment`: `recommended_payout`, `rationale_facts: list[str]`.
- `Handoff`: `from_agent`, `to_agent`, `payload` (структура / tagged union, не `str`), `tokens_used`, `cost_usd`.
- `PayoutDecision`: `approved: bool`, `approver: str | None`, `amount`.

**Чего не делать:** не добавляй `raw_llm_output` или `completion` на границе. Парсинг — внутри агента (глава 3). Не правь тесты «чтобы проходили» — почини модели. Никакого `str` там, где должно быть поле.
</Scaffold>

Минимум полей, которые стоит заложить:

- Intake: `claim_id`, `narrative`, `claimed_amount`, `incident_date`, `attachments_meta`.

- Fraud: `risk` (`low`|`medium`|`high`), `flags: list[str]`, `send_to_human: bool`.
- Assessment: `recommended_payout`, `rationale_facts: list[str]`.
- Handoff: `from_agent`, `to_agent`, `payload` как tagged union, `tokens_used`, `cost_usd`.
- PayoutDecision: `approved: bool`, `approver: str | None`, `amount`.

Тест в скелете проверяет, что невалидный хендофф поднимает `ValidationError`, а валидный — нет. Сначала он может быть skip — сними skip, когда модели готовы.

```text
3 passed in 0.06s
```

Как тип отвергает свободный текст — литералы вместо `str` (паттерн, не решение):

```python
from typing import Literal
from pydantic import BaseModel

class ClassifierResult(BaseModel):
    claim_id: str
    claim_type: str
    priority: Literal["low", "medium", "high"]  # "urgent" → ValidationError
    confidence: float
```

<Action title="Запрети свободный текст на границе">
В типах не должно быть поля `raw_llm_output`, которое оркестратор «как-нибудь» парсит. Парсинг — внутри агента, наружу — только модель.
</Action>
