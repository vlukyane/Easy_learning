Payout — не ещё один LLM-шаг. Это функция, которая принимает `Assessment` и `Approval`.

<Scaffold path="projects/casefile/src/hitl.py">
`request_approval(assessment) -> PayoutDecision`. В учебной CLI — `input()`: да/нет и имя аппрувера. Нет ответа человека — `approved=False`, вызова `execute_payout` нет.

**Что сделать:** зафиксируй константу `PAYOUT_HUMAN_THRESHOLD` (в `.env.example` уже есть). В учебной версии безопаснее требовать человека всегда (`0` = любой amount). Отказ пиши в трассу как `payout_denied_by_human`.

**Чего не делать:** не давай агенту инструмент `approve`. Approve — только оркестратор после человека. Не пропускай шаг молча, если человек отказал.
</Scaffold>

<Scaffold path="projects/casefile/src/payout.py">
`execute_payout(decision)` — не LLM-шаг, обычная функция. Проверяет `approved is True` и `amount` по политике (`<= assessment.recommended_payout` или явный порог). Иначе исключение.

**Что сделать:** без `approved=True` — `PermissionError` (скелет уже так делает, не снимай проверку). После флага — запись в учебный ledger (файл или список), не реальные деньги.

**Чего не делать:** не вызывай `execute_payout` из агента assessor. Не обходи гейт из REPL «просто чтобы проверить сумму».
</Scaffold>

Правило пилота: **любая** выплата требует человека, либо выплата выше порога (например $1000). Выбери одно и зафиксируй в коде константой `PAYOUT_HUMAN_THRESHOLD`. План говорит: «a human before any payout» — в учебной версии безопаснее требовать человека всегда, порог оставить для ветки «auto-deny vs ask».

```python
def execute_payout(decision: PayoutDecision) -> None:
    if not decision.approved:
        raise PermissionError("payout requires human approval")  # эту проверку не снимай
    ...  # ledger только после флага
```
